# 共享记忆（Claude 与 Codex 共用这一份）

Claude 通过 ~/.claude/CLAUDE.md 引用本文件（`@~/agent-hub/memory/global.md`），Codex 通过 ~/.codex/AGENTS.md（软链）读取本文件。
详细内容放在同目录 global/、projects/ 下；需要细节时再打开，不必每次全读。

## 记忆怎么用、怎么写
- 规则/偏好直接照做；稳定事实直接用，用时出错再查并当场修正记忆。
- 易变状态（进度、分支是否已 push 等）只在据此动手前用 git 等确认，并尽量少记——真相在 git 里。
- 只有正在和用户对话的调度者可以写记忆；被派活的一方不写。写入前先查有无同主题文件，更新而非重复。
- 只记用户亲口说的或实际验证过的结论，不记推测；易变状态注明日期（YYYY-MM-DD）。
- 跨项目通用 → global/；只与某仓库有关 → projects/<仓库目录名>/README.md。
- 记忆与当前代码/实际验证矛盾时，以代码和验证为准，当场修正。
- 在某个仓库里工作时，先读 projects/<仓库目录名>/README.md（存在的话）。

## 多模型协作
- 用户主要和一个模型对话，它是默认调度者（组长）；另一家被直接使用时同样可以调度。
- 按擅长派工，顺带均衡 Claude/Codex 额度（不追求对半，避免耗光一家）；DeepSeek 能干的（含中文文案）先给它；需求不明确时 Claude 出方案、Codex 执行。
- 多方在同一工作目录并行改动时，派活前明确每方的文件归属，不交叉写同一文件。
- 自己做还是派出去：按轮数不按行数。先估自己做要几轮调用 N（`ledger.mjs task start --estimate N` 记下，事后校准）。N≤2 自己做；N≥4 且说明能一次写清 → 派；N≈3 看说明难度和返工概率。会话越长越倾向派。
- 不做例行的交叉复核。同一问题修两次仍没解决，或用户说"还是不行"，停下来把现象 + 已试方法交给另一家用全新视角排查。
- 每件活做完给用户一行交代：怎么做的（自己/派给谁）、几轮、测试是否通过、哪里没把握。
- 审查按风险分级：小改动只需自动检查 + 派工者看 diff，高风险才请另一家交叉审。
- 互相派活时把背景、约束、验收标准写完整；对方的产出认真对待、具体反馈。
- 硬规则：敏感任务（鉴权/密码/token/密钥/支付等或 risk=high）绝不下放 DeepSeek（代码强制）；DeepSeek 最多 2 次，失败即升级给另一家大模型。
- 正式的开发派活/验收流程用 skill `team-dev`（Claude 用 /team-dev、Codex 用 $team-dev 显式调用）。
- 换任务开新会话最省：组长消耗 ≈ 调用次数 × 上下文大小。
